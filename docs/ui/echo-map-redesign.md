# 逐次3Dマッピング：救助判断を支える表示設計

2026-10-30 / 対象：Purumogu Search 3.2 / 状態：設計提案。Unity実装・実地検証は未実施。

## 前提と設計判断

右画面を「反響で削り出された半透明の空洞モデル＋同期する断面＋優先確認カード」に再構成する。空間の美しさより、利用者が観測範囲、不明部分、人候補、次の確認先を短時間で区別できることを優先する。

現在のコードは距離レイ、推定姿勢、音の方向・強度・変調、温度、模擬ガス・水深を扱う。音の発射時刻と反射到達時刻を持つ能動ソナーではない。現行データで出す波紋は「観測更新パルス」と明記し、実測の反射波・音速・反射強度に見せかけない。能動音響の拡張時だけ実測反響へ切り替える。

「3秒以内」は利用者試験で検証する目標。「90〜95%」は表示に要求する水増し率ではない。観測できた範囲と、検証された高信頼推定の範囲を広げる探索上の目標とする。実際の値が低ければ、そのまま低く表示する。

## 1. デザイン方針

1. **判断**：右上に「優先確認A」と理由、次の観測先R1を提示する。候補の追認に全ノードを集めず、確認隊と探索隊を分ける既存方針を維持する。
2. **空間**：障害物は厚みのある面と切断面のハッチ、観測された空洞は床と壁面の内側に残る負の空間で表す。単に黒い部分を空洞と呼ばない。
3. **根拠**：色だけに頼らず、実線／破線／点描／暗い遮蔽を使い分ける。確定・推定の境界をまたいで面を一体化しない。
4. **時間**：新しく裏づけられた輪郭だけを短く明るくし、直近の更新方向を残す。常時点滅や自動旋回はしない。

「観測確定」はセンサーに裏づけられた表示区分であり、実物との完全一致、構造安全性、通行安全を保証する用語ではない。凡例の説明から確認できるようにする。

## 2. 画面レイアウト

既存の左上シミュレーション、左下ノード状態、右下評価という役割を保つ。右上766×406の通常表示では主役を絞り、右上パネルを拡大すると断面・カードの詳細を展開する。右下の真値評価を救助判断のカードに混ぜない。

```text
右上：逐次3Dマッピング                                   [拡大]
観測範囲バー：観測／高信頼推定／低信頼推定／未観測（常時表示）
[俯瞰3D | 上面2D | 縦断面 | 横断面]        [表示レイヤー]
┌─────────────────────────┬───────────────┐
│ 3/4俯瞰：空洞・瓦礫面・未観測の暗域   │ 優先確認A      │
│ Aピン ── 引出線                     │ 音：高／温度：中│
│ R1：次の観測先                      │ 次：別方向で確認│
├─────────────────────────┤ 次の観測 R1    │
│ Aを通る自動断面：床／瓦礫／空洞／不明 │ 観測が不足     │
│ [断面位置]  [この断面を固定]          │ 危険情報は下段  │
└─────────────────────────┴───────────────┘
凡例：観測確定／高信頼推定／低信頼推定／未観測／人候補／危険候補
```

拡大時は左70%を立体＋断面、右30%をカードに使う。通常時は選択中の1カードと小さな断面を表示し、他候補は件数と短い行で示す。日本語の本文は通常14px、見出し16〜18px、最低12pxを目安に実機で確認する。情報を収めるための極端な文字縮小はしない。

表示レイヤーには「反響表現」「推定補完」「人候補強調」の独立した切替を置く。OFFでも凡例・候補件数・未観測率は消さない。「人候補強調OFF」は脈動や拡大だけを止め、基本ピンとカードを残す。「推定補完OFF」は推定形状を隠すが、その場所を観測済みに塗り替えない。

初期カメラは低歪みの3/4俯瞰。上面2D・断面は平行投影。ドラッグは0.15度/pxを初期値、上下角20〜75度、ロール禁止。ホイール1段で約8%拡縮、0.15秒程度の補間を初期値とし、感度設定・即時停止に対応する。カード、スライダー上ではカメラを動かさない。候補を選んでも主カメラは自動で回転しない。

## 3. 色・線・透明度・動き

数値は初期デザイン値であり、視認試験後に調整する。背景#071116、文字#EAF4F6、補助文字#A6BBC3。意味色は白、シアン、橙、赤に絞る。

|対象|色／形|面の不透明度の初期値|線と動き|
|---|---|---:|---|
|観測確定|淡いシアンの面、厚みが読める陰影|80〜95%|実線1.5〜2px。新しい根拠の輪郭だけ短く強調|
|高信頼推定|シアンの薄い面|20〜35%|破線。実測面と独立した境界|
|低信頼推定|低彩度シアン、粗いハッチ／点描|5〜12%|疎な点線。「要再観測」を併記|
|未観測|青黒の不明領域|暗い遮蔽を維持|斜線と「未観測」。奥が空洞に見える透明化は禁止|
|人候補|橙#FFB454、ピン＋A/B文字|小さい固定ピン|選択時に一度だけ穏やかな拡大。常時点滅なし|
|危険候補|赤#FF6173、三角＋ガス／浸水／閉塞の文字|局所的に10〜18%|記号・ハッチ・境界。危険の強度と確信度を混ぜない|
|観測更新|白〜シアン#80E5EC|最大25%|0.6〜1.2秒で広がる短い波。地図を覆わない|

人候補と危険が重なる場所では両方の記号を残す。形状面そのものを全面赤に染めず、空洞・障害物の輪郭を読めるようにする。暗色背景、グレースケール、色覚差、低輝度の画面でも線種と文字で区別できるか確認する。

## 4. 反響マップ風の表現仕様

### 現行の観測更新モード

- 新しい観測パケットに対応するノードだけが小さな波を発する。最大同時3波、全体で最大毎秒2イベントを抽出して表示する。表示を間引いても推論の観測は間引かない。
- 発信位置は推定姿勢であり、位置誤差を持つ。波は「更新の手がかり」で、未観測の壁や空洞を実際に測ったことにはしない。
- 波が届いたように見えるタイミングで光らせるのは、そのパケットにより更新された既知の面だけ。真値メッシュへのレイキャストで輪郭を出さない。
- 新規面の輪郭は0.3秒強調、直近2〜3秒の履歴を低輝度で残す。履歴が消えても構造の推定状態を変えない。
- 音方向が得られた場合は短い方位扇を選択ノードだけに出す。音の方向と壁までの距離を混同しない。
- 再生停止で更新演出も停止。低モーション設定は波を消し、更新した輪郭の静的マークに置き換える。

### 能動音響を追加する場合

`pulse_id / emission_time / emitter_pose / received_time / amplitude / receiver_pose / measurement_uncertainty`を記録し、実測とシミュレーションを明示する。距離は発射と受信の対応が取れたデータから推定し、複数反射・遮蔽・温度依存・姿勢誤差を扱う。見やすい速度へ時間を伸ばす場合は「時間拡大表示」と表示する。

NOAAは能動ソナーの送信と反射受信、受動ソナーの受信のみを区別している。この区別をUIにも採用する。ただし水中ソナーの説明は、空気中の瓦礫環境での測定精度を裏づけるものではない。

## 5. 人候補の強調表示

地図には橙ピンと大きいA/Bの識別子、カードには「優先確認A／人候補・未確認」を出す。実在を断定する「要救助者確定」は使わない。左の真値表示用の赤ボールを右の推論地図へ入力しない。

カードの固定項目：

1. 今取るべき行動：「別方向から音・温度を再確認」
2. 根拠：「音反応 高／温度反応 中／独立4ノード」
3. 空間情報：「観測された空洞と連結」または「連結未確認」
4. ノードの到達可能性：「経路推定あり／未確認」。救助隊員の進入可能性と分ける
5. 鮮度：「最終反応2秒前」、順位スコア0.82なら「順位スコア0.82・確率ではない」

上記の文言は対応する根拠が実際に得られた場合だけ出す。現行のCueには音・温度別の根拠が送信されないため、Unityだけで文章を捏造しない。データがなければ「根拠詳細未取得」。

面の裏にある候補には引出線と「遮蔽あり」の記号を使う。常時X線のように空洞を透視させない。不確かな位置は小さな範囲表示を添え、範囲が未校正なら「位置範囲は目安」。大きい球のワイヤーフレームで全景を覆わない。カード選択で同じ候補IDを立体・上面・断面に同期し、利用者が選んだ時だけ断面を更新する。断面固定を許す。

## 6. 観測確定・推定・未観測

次の2軸を必ず独立に保持する。

|軸|区分|目的|
|---|---|---|
|空間の状態|障害物／空洞（free）／不明|どこが埋まっていて、どこに空間があるか|
|根拠の状態|観測／高信頼推定／低信頼推定／未観測|どの程度裏づけがあるか|

占有確率が低いだけのセルを、根拠が十分な空洞と同一視しない。未観測は「何もない」ではない。これはoccupied/free/unknownを分けるOctoMapの考え方と整合する。

座標グリッドは位置を読むための補助であり、観測済み床とは別レイヤーにする。観測済み空洞の床・輪郭はfreeを裏づけるレイの通過セルから作り、背景のグリッドやシミュレータの床をそのまま観測済みとして描かない。

「高信頼推定」は独立評価データでセル種別ごとの信頼度を校正してから有効化する。現行の`completion_confidence`は形状族の分類スコアであり、そのままセル単位の高信頼度に使わない。校正前は高信頼推定0%とし、推定は低信頼側の「推定・未校正」にまとめる。凡例の高信頼推定は残し「校正前のため未使用」とする。

範囲バーは、利用者が決めた捜索対象ROIを母数として4区分の体積比を表示する。表示された三角形や画面上のピクセル数から計算しない。ROI不明なら百分率を出さず、観測体積と「対象範囲未設定」を出す。表示切替で比率は変えない。ROI変更時は比較不能になることを明示する。安全率・IoU・検出精度とは別の指標である。

校正後の例：観測78%、高信頼推定15%、低信頼推定2%、未観測5%。「把握95%」のように低信頼推定まで合算した見出しは出さない。表示範囲が95%に達しても観測78%は78%のまま残す。画面案の数値は構成検討用の仮データ。

表面を滑らかにする処理は同じ根拠区分の局所内だけ。未知の隙間を橋渡ししたり、小さい通路を閉じたりしない。評価セルは現在の5cmを維持し、1cmで描いたから1cmの測量精度があるとは表示しない。細部を画面に適合させる場合は分解能と位置誤差を併記する。

## 7. Unity向け実装案

### 段階A：現行プロトコルで実装できる表示

- `RescueMapView.cs`の観測セル面・外形線を再利用し、主表示を面＋輪郭に統一。点群は検証用の詳細レイヤーに移す。
- 同じmap snapshotを使うカメラ2台とRenderTexture2枚を使う。主カメラは3/4、断面カメラは平行投影。推論を2回実行しない。
- 障害物表面と切断面を別メッシュにする。単なるクリップシェーダーだけでは切断面が塞がらないため、切断セルの面または2Dセルテクスチャで断面を描く。
- 観測・推定を別メッシュ／別マテリアルに分離。観測物体の外面は基本不透明とし、選択断面の前側を切る。半透明ソリッドを何層も重ねる方式は避ける。
- 推定は専用深度・破線輪郭。危険ハッチ、人ピン、ラベルは独立レイヤー。候補が面に隠れる時は引出線と遮蔽表示を使う。
- UI Toolkitまたは既存GUI内の小さなプレゼンターを設け、表示切替と選択IDを一本化する。段階導入では既存OnGUIを保ち、全画面のUI移行を必須にしない。

### 段階B：必要なRust→Unityデータ拡張

|追加データ|理由|
|---|---|
|セルの観測種別、最終観測時刻、異なる観測ノード数、矛盾フラグ|観測の鮮度と裏づけを表示する|
|推定の校正バージョン・検証結果・セル区分別の信頼度|高信頼表示の根拠を確保する|
|Cueの安定したID、音／温度の寄与、根拠ノードID、更新時刻|候補A/Bの入れ替わりと架空の説明を防ぐ|
|空洞連結の経路、確認済み区間と推定区間|連結と到達可能性の説明を分ける|
|観測イベントID、根拠種別、関連セルキー|更新パルスと新しい面を結び付ける|
|接触・停止・通信断の時刻と推定位置、関連不確かさ|閉塞「疑い」を示す。単独イベントで壁確定にしない|
|次の観測提案の対象、理由、根拠、情報不足項目|R1カードから具体的な観測行動につなぐ|
|ROI、区分別体積、対象未設定状態|範囲バーを定義された母数から計算する|

プロトコルをバージョン化し、古いデータには「未取得」を表示する。UI表示でシミュレータの真の壁・人座標・真の空洞を参照しない。

### 推奨構成

`EvidenceMapSnapshot`（読み取り専用）→`SurfaceRenderer` / `SliceRenderer` / `ObservationPulseRenderer` / `PriorityPresenter`。

`MapDisplayState`に投影モード、断面位置、選択Cue ID、3つのレイヤー切替を保持。表示操作は推論や観測率を変更しない。候補選択とノードへの指令も分離する。

描画は変更されたチャンクだけ更新。16セル角程度のチャンクを初期案とし、現機で測定して調整する。面と断面は2〜5Hz、パルスとカメラはフレーム更新。48ノード・15シーンでフレーム時間、GC割当、メッシュ更新時間を計測して採否を決める。VFX Graphや重いボリュームレイマーチを必須にしない。

## 8. 分かりやすくなる理由と検証

点群は点の密度を解釈する必要があった。面と断面にすると、壁の厚み、通路のつながり、瓦礫の上／下を比較できる。候補ピンとカードの同じIDを追うだけで、反応の位置と次の行動が対応する。観測状態は色以外にも線種で表すため、淡い面を確定構造と誤認しにくい。これは設計上の仮説であり、3秒で判断できることを検証した結果ではない。

### 具体的な利用例：3つ

1. **優先確認A**：複数ノードの音反応と温度反応が一致。橙ピンを選び断面で空洞との位置関係を確認。「別方向で再確認」を提案し、少数ノードを確認に回す。残りのノードは未観測R1を探索する。順位スコアを生存確率と呼ばない。
2. **R1・未観測**：壁の裏が暗いハッチで残り、推定壁は破線。空洞と決め付けず、「別経路から距離観測」を次の調査にする。観測不足を表示の穴ではなく探索の対象として扱う。
3. **危険候補G1**：人候補への接近側にガス反応。赤い三角とハッチを併記し、「ガス反応側を避けた観測経路の再確認」を促す。未観測の迂回路を安全な進入路として案内しない。模擬ガス値をppmや%LELへ読み替えない。

### メリット

- 空洞・障害物・不明が形でも分かる。
- 人候補の位置と理由、次の確認先がまとまる。
- 推定を消して実観測だけを見る比較ができる。
- 既存の面メッシュとRust推論を再利用でき、段階的に実装できる。

### デメリット／残る弱点

- 半透明面には前後関係の誤読がある。断面と不透明な切断面で補うが、利用者試験が必要。
- 滑らかなモデルは実際より精密に見えやすい。元の評価分解能と姿勢誤差を併記する必要がある。
- 高信頼推定、候補の説明、閉塞の根拠にはサーバー側の追加出力と校正が必要。UIだけで実現したことにはできない。
- 「音響反響」を実測として見せるには現在のセンサー契約が不足する。波の見た目だけでは解決しない。
- 現在の研究環境は既知の形状族に依存する。表示改良は未知の災害現場での推定精度や安全性を証明しない。

### 代替案

本番で3Dの前後関係が読みにくい場合は「上面2D＋固定断面」を初期表示にする。演出は弱くなるが、平面位置と接近方向の比較が容易になる。提案した3/4＋断面と同じデータ・カードを使い、利用者試験で初期表示を選ぶ。

### 検証と今日着手できる順番

1. 仮データの画面案で、観測・推定・未観測・候補の4項目が区別できるかを確認する。
2. 既存MapReplyのみで、面＋輪郭、投影4種、断面、候補IDの同期、推定ON/OFFを実装する。校正・根拠詳細の未取得は明示する。
3. Rustの根拠メタデータとROI集計を追加し、録画された同一観測列で表示の一貫性を検証する。
4. 初見の協力者へ3秒間だけ画面を提示し、「分かっている範囲／未観測／人候補／次の確認先」を回答してもらう。応答中央値3秒以内・正答率90%以上を仮の目標とし、未観測を安全と取り違えた件数を独立に記録する。達成していなければ情報量・初期投影を調整する。
5. 15シーン×24/36/48台で、低観測、誤反応、危険重複、切断、候補消失、通信遅延の表示を確認する。モデル精度のIoU・適合率・再現率95%条件とは別に評価する。

## 一次資料と参照範囲
